Development ​

This page summarises the conventions and tools of the kura-web repository. It does not replace the reference documentation: business rules live in kura-docs, and any change that touches them must be updated in the same pull request.

Setting up ​

See Getting started for the prerequisites and composer setup. Once the database is in place:

bash
composer dev

The command runs the PHP server, the queue worker, Vite and the logs in parallel.

Commands ​

CommandEffect
composer setupFull install: dependencies, .env, key, migrations, seeders, storage, assets
composer devServer, queue, Vite and logs
composer testconfig:clear, Pint check, Larastan, then Pest
composer ci:checkcomposer test + ESLint, Prettier and vue-tsc
composer lint / composer lint:checkPint fixing / checking
composer types:checkLarastan (PHPStan level 7)
pnpm lint / pnpm lint:checkESLint fixing / checking
pnpm format / pnpm format:checkPrettier
pnpm types:checkvue-tsc --noEmit
php artisan test --compactPest suite only

The GitHub CI (lint-test) calls the organisation's reusable workflow, which runs Pint and Pest after a pnpm build. ESLint, Prettier, vue-tsc and Larastan are not re-run on GitHub: run them locally with composer ci:check before pushing.

Conventions ​

  • Code language: identifiers, tables, columns, classes, routes and file names in English. French is reserved for the UI translation files and user-facing documents.
  • Branches: master by default; feature/<short-name>, fix/<short-name>, chore/<short-name>.
  • Commits: Conventional Commits style — feat:, fix:, chore:, with a short description.
  • Package manager: pnpm only. Never commit package-lock.json or yarn.lock.
  • PHP: Pint with the Laravel preset; braces on every control structure; explicit parameter and return types; promoted constructor properties.
  • Statuses: always PHP enums (App\Enums), never free-form strings. Values are in English, snake_case.
  • Amounts: FCFA, DECIMAL(12,2), excluding tax, never a float.
  • References: generated by the HasYearlyReference trait, in the PREFIX-NB-YYYY-XXX format.
  • Authorisation: cross-cutting Gates defined in AppServiceProvider, consumed by can:*, Gate::authorize and useAccess. There are no per-model Policies.

The lifecycle of a change ​

  1. Read kura-docs (business-logic.md, architecture.md, api.md) and the relevant ADR.
  2. Create the branch and, if behaviour changes, the test that describes it.
  3. Write the code following the neighbouring patterns — same controller, Form Request and Inertia page structure.
  4. Run the targeted tests, then composer ci:check.
  5. Update kura-docs in the same pull request if a rule, an API contract, a data model or a decision changes.

Tests ​

Tests are written with Pest 4, under tests/Feature (one folder per module) and tests/Unit. Feature tests use RefreshDatabase and the model factories; custom states (->withRole(), ->organization(), ->forCohort()) avoid building graphs by hand.

php
it('suspends Sève access thirty days after the due date', function () {
    $enrolment = billedEnrolment();
    $this->travel(31)->days();

    $this->artisan('billing:run')->assertSuccessful();

    expect($enrolment->fresh()->status)->toBe(EnrolmentStatus::Suspended);
});

Good practices:

  • test observable behaviour (status, issued invoice, sent notification), not the implementation;
  • freeze time ($this->travelTo(), $this->travel()) whenever a rule depends on a date;
  • fake side effects (Notification::fake(), Storage::fake(), Queue::fake()) and assert what matters;
  • cover the nominal case and the failure branches that carry a business rule;
  • do not duplicate the validation tests Laravel generates.

To run a single file or a single test:

bash
php artisan test --compact tests/Feature/Billing/BillingTest.php
php artisan test --compact --filter="suspends Sève access"

Frontend ​

  • Inertia pages under resources/js/pages, one folder per module. Each page declares its typed props in resources/js/types.
  • Reusable components under resources/js/components: check what exists before writing a new one.
  • Composables: useAccess for permissions, useMainNav for the menu, useLocale for the language, useAppearance for the theme.
  • Wayfinder: URLs and actions come from @/actions and @/routes, never from a hand-written string. The plugin is configured in vite.config.ts with formVariants: true; generated files are versioned.
  • Styles: Tailwind CSS v4 and shadcn-vue components (components.json, new-york-v4 style). Palette, typography and spacing follow the NextBoxx design system.

Internationalisation ​

  • vue-i18n with JSON files per domain under resources/js/lib/locales/fr and resources/js/lib/locales/en.
  • The locale is stored on the account and applied by the SetLocale middleware; it can be changed from the profile.
  • Every new visible string goes through a translation key in both languages. Emails and PDFs use the recipient's language.
  • Business labels (statuses, payment methods, reasons) are formatted in resources/js/lib/*.ts, not in components.

Known pitfalls ​

  • N+1: list pages should load their aggregates with withCount, withSum and with, not by calling a relation or a method per row. Watch the dashboards, reporting and funder areas in particular.
  • Large models: Enrolment, Invoice, Cohort and CompanyRequest mix queries, rules and formatting. Extract into a service or an action rather than adding to them.
  • Concurrency: yearly numbering, instalment issuing and payment recording rely on unique constraints and transactions. Keep the locks (lockForUpdate) and provide a clean retry on collision.
  • Idempotency: scheduled commands (billing:run, seve:sync, events:run) can be replayed. A second pass must not double an invoice or send a message twice.
  • Inertia contracts: props are hand-built arrays duplicated in resources/js/types. Evolve them together, otherwise vue-tsc or runtime breaks silently.
  • PHPStan level 7: collection types and nullable returns are strict. Prefer value objects and enums to untyped associative arrays.
  • Security: PDF documents live on a private disk, served by authorised routes; public links are signed or token-based and single-use. Never expose a storage path.
  • Personal data: refused candidatures are anonymised after 12 months, inactive accounts deactivated after a year. Any new table holding personal data must plan its purge.
